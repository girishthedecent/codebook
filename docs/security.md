# Security review

The checklist from PLAN.md 17.1, item by item: what protects it, how it was checked, and
the result. "Test" points at the test that fails if the protection goes away.
`tests/security.test.ts` holds the checks that had no test of their own before this review.

## Dependency audit

`pnpm audit --prod` on 2026-10-25 found five advisories. undici was upgraded to 8.12.2 the
same day (the crawler fetches pages from servers users choose, so its DoS mattered most); the
audit now reports the two below.

| Severity | Package     | Installed | Fixed in | Advisory                                                                | Via                                                  |
| -------- | ----------- | --------- | -------- | ----------------------------------------------------------------------- | ---------------------------------------------------- |
| high     | multer      | 2.4.0     | 2.5.0    | DoS through a pending async `fileFilter` after the request is torn down | direct (PDF upload); our `fileFilter` is synchronous |
| high     | body-parser | 2.3.0     | 2.4.0    | DoS through trailing bytes after a compressed body                      | express 5.3.0, swagger-ui-express                    |

Both fixes were released on 2026-10-22. Dependencies are only taken once a release is about
two weeks old, so these two wait: upgrade multer to 2.5.0 and body-parser to 2.4.0 (through
express's range or a pnpm override) after 2026-11-05, then audit again. Until then the
body-parser one is the exposure that counts: any JSON route accepts a compressed body.

## Routes outside `/api/v1`

- `/api/auth/*`: better-auth. Body read with a size cap before it gets the request; origin
  check on (tests included); per-IP rate limit in dev and production; guest sign-in capped
  per IP ahead of it (`guestSignIn`).
- `/api/inngest`: signed requests only in production (item 3).
- `/openapi.json`, `/docs`: public, read-only.
